Как устроена модель

Уравнения движения

Flexia не редуцирует координаты: каждое тело описывается тремя абсолютными координатами (x, y, θ), а каждая голономная связь добавляет свой блок множителей Лагранжа λ. Система записывается как индексированная DAE:

\[ M \dot{q} = f(q) + \Phi_q^{\mathsf{T}} \lambda + u_{\text{targets}}, \qquad \Phi(q) = 0 . \]

Здесь M — матрица масс, q — координаты и скорости, f — внешние силы и кинематические соотношения q̇ = v, Φ — уравнения связей, λ — реакции связей. Такая форма даёт простую сборку: каждая связь независимо дописывает свои строки в правую часть.

Практические следствия:

  • размер вектора состояния больше числа физических степеней свободы;
  • матрица масс вырождена: в позициях λ стоят нули;
  • жёсткость снимается интегрированием в комплексной плоскости (метод CROS, см. главу «Расчёт»).

Вектор состояния

Состояние — плоский Vector{Float64} фиксированной длины. Для тела с номером i (нумерация с 1 в порядке добавления в систему):

Блок Индексы Что там
Позиция тела i 6i-5 … 6i-3 (x, y, θ)
Скорость тела i 6i-2 … 6i (vx, vy, ω)
Множители связи k подряд после тел number_of_dofs(connector) значений
Время последний элемент t, при этом rhs[end] = 1, mass[end, end] = 1

Инварианты:

  • number_of_dofs(sys) = last_lm_dof(sys) + 1 — полная длина состояния;
  • last_body_dof(sys) = 6 * number_of_bodies(sys);
  • блок λ связи k занимает lmdofs[k] - number_of_dofs + 1 … lmdofs[k], конкретные индексы возвращает get_lms(sys, connector).

Пример: два тела и две связи (заделка, 3 λ, и шарнир, 2 λ) дают 12 + 5 + 1 = 18 элементов состояния.

Отдельно от состояния существует вектор обобщённых координат: в нём упакованы только позиции тел, 3 * number_of_bodies(sys) значений. Индексы для тела i возвращает get_body_generalized_dofs; этот вектор используется при проверке кинематики связей и в set_pos_state_value!.

Доступ к индексам

i = get_body_position_dofs(sys, body)   # SVector{3,Int}: (x, y, θ)
j = get_body_velocity_dofs(sys, body)   # SVector{3,Int}: (vx, vy, ω)
k = get_lms(sys, joint)                 # lambda indices of this connector

Все три функции требуют, чтобы сущность уже была добавлена в систему (add!): до этого её индекс равен -1.

Матрица масс

assemble! собирает sys.mass один раз на текущую структуру:

  • единичный блок I(3) для позиционных dof;
  • Diagonal([m, m, J]) для скоростных dof;
  • 1.0 в позиции слота времени;
  • нули на месте λ.

Матрица намеренно вырождена, поэтому обращать её нельзя. Её блок для тел используется в CROS и в расчёте ускорений датчиками.

Правая часть

sys.rhs(state) — замыкание, которое складывает вклады:

  1. тел: q̇ = v и пользовательские силы из body.forces;
  2. связей: реакции λ в скоростные dof и уравнения связей в dof λ;
  3. сил: моменты пружин и внешние силы;
  4. вычитает уставки приводов sys.targets и принудительно ставит rhs[end] = 1.0.

Якобиан sys.jacobian — плотный якобиан этой правой части, посчитанный ForwardDiff. Он пересчитывается на каждом шаге интегрирования.

Жизненный цикл системы

# 1. Create the entities.
bd  = Body2D(1.0, 0.1; length = 1.0)
jnt = HingeJoint(ground, bd)

# 2. Add them to the system. Addition order defines numbering and indices.
sys = MBSystem2D()
add!(sys, bd)
add!(sys, jnt)

# 3. Build the mass matrix, right-hand side, Jacobian and target slots.
assemble!(sys)

# 4. Set the initial state and solve.
initial = zeros(number_of_dofs(sys))
set_initial_position!(initial, sys, bd, SA[0.0, 1.0, 0.0])
sol = simulate(sys, initial, 0:0.001:10.0)

Порядок важен:

  • Тела добавляются до связей. add! для связи читает last_lm_dof(sys) и last_body_dof(sys), поэтому тела должны быть уже в системе.
  • Связи и силы добавляются до assemble!. После сборки структура зафиксирована; если добавить сущность позже, нужно собрать систему заново.
  • assemble! ничего не возвращает. Флаг готовности лежит в sys.assembled.

Начальные условия

Начальное состояние — обычный Vector{Float64} длины number_of_dofs(sys):

initial = zeros(number_of_dofs(sys))
set_initial_position!(initial, sys, body, SA[x, y, θ])
set_initial_velocity!(initial, sys, body, SA[vx, vy, ω])   # only if nonzero

Про начальные условия стоит помнить следующее.

  • Согласованность. Позиции должны удовлетворять уравнениям связей (совпадающие точки шарниров, ползун на своей направляющей и т. д.). Иначе первые шаги уйдут на переходный процесс, а при больших невязках расчёт может разойтись.
  • Множители λ обычно нулевые. Реакции в начальном состоянии не вычисляются автоматически: если на механизм действует нагрузка, на первых шагах будет короткий переходный процесс установления λ.
  • Скорости. Нулевые скорости — допустимое начальное состояние, но не равновесие: под гравитацией механизм начнёт двигаться.

Единицы и соглашения

  • Все величины в СИ. Момент инерции — относительно центра масс тела.
  • Углы в радианах; положительное направление — против часовой стрелки.
  • Координаты точек на теле — локальные, с началом в центре масс.
  • Точки крепления связей задаются на каждом из двух тел в его локальной системе координат.
  • Гравитация — обычная внешняя сила: body.forces[2] = (state, t) -> -m * g.
  • Время — последний элемент состояния: функции сил и уставки приводов получают его как state[end] или как аргумент t.

Точки расширения

Новая сущность (например, трёхмерный шарнир или неголономная связь) требует:

  1. mutable struct от соответствующего абстрактного типа (AbstractJoint2D, AbstractForce2D, AbstractActuator2D, AbstractSensor2D) с полем index::Int64 = -1;
  2. number_of_dofs(::T) — сколько λ добавляет сущность (0 для сил);
  3. get_lms(sys, x) — индексы λ в векторе состояния;
  4. add_to_rhs!(rhs, state, sys, x) — уравнения связи и реакции;
  5. для связей — compute_kinematic_residual! (проверка кинематики);
  6. для приводов — propagate_targets! и update_jacobian!;
  7. для отрисовки — компаньон и метод _draw_...! (см. главу «Визуализация»);
  8. экспорт имени в src/Flexia.jl после списка include.
