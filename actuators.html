Приводы

Приводы — позиционные: они поддерживают заданное значение координаты (угла или расстояния), а не развивают заданную силу. Привод добавляет в систему одно уравнение связи и один множитель λ. Ограничений на момент или силу привода нет.

Оба привода — коннекторы, поэтому добавляются через add! и участвуют в assemble! наравне со связями.

PositionMotor2D — моментный привод на шарнире

Поддерживает заданный относительный угол двух тел шарнира:

motor = PositionMotor2D(hinge, 0.0, 0.0)   # (target angle, target rate)
add!(sys, motor)
  • target_angle — целевой относительный угол θ2 - θ1, рад;
  • current_velocity — скорость изменения цели, рад/с;
  • number_of_dofs(::PositionMotor2D) == 1 — одно уравнение, один λ.

Смена цели:

settarget!(motor, π / 2, 0.0)               # hold 90 degrees

Если цель зависит от времени, её нужно обновлять перед каждым шагом — для этого есть sys.prestep:

sys.prestep = state -> begin
    t = state[end]
    settarget!(motor, π * t, π)             # target angle grows at pi rad/s
end

current_velocity — это производная цели по времени. Она попадает в якобиан системы и должна быть согласована с target_angle: если задать цель π * t, а скорость 0, интегрирование будет считать, что цель не меняется, и появятся ошибки слежения.

PositionLinearActuator2D — линейный привод на ползуне

Поддерживает заданное положение второго тела вдоль оси первого:

actuator = PositionLinearActuator2D(slider, 0.0, 0.0)   # (target position, target rate)
add!(sys, actuator)
  • target_position — расстояние между точками ползуна вдоль оси, м;
  • current_velocity — скорость изменения цели, м/с;
  • number_of_dofs(::PositionLinearActuator2D) == 1.
settarget!(actuator, 0.25, 0.0)             # move to 0.25 m

Пример с движущейся целью:

const A = 0.5
const Ω = 2.0
sys.prestep = state -> begin
    t = state[end]
    settarget!(actuator, A * sin(Ω * t), A * Ω * cos(Ω * t))
end

Как это работает внутри

  • Привод хранит цель в своих полях; propagate_targets! переносит её в sys.targets при вызове update_targets!.
  • assemble! создаёт sys.targets и заполняет его начальными значениями.
  • На каждом шаге CROS вызывает sys.prestep(state), затем update_targets!(sys), затем считает sys.rhs(state).
  • sys.rhs вычитает уставки из строк λ: получается уравнение θ2 - θ1 - target = 0 (или s - target = 0 для линейного привода).
  • Реакция привода — соответствующая строка λ в решении. Её можно достать через get_lms(sys, actuator).

Ограничения и тонкости

  • Позиционная связь, а не силовая. Привод удерживает координату и «подстраивает» момент/силу под нагрузку. Предела момента нет: при заклинивании нагрузки могут быть сколь угодно большими.
  • Множитель λ позиционного линейного привода не равен физической силе. Формулировка связи по положению даёт множитель, в котором инерционная часть входит с другим знаком, чем в уравнении движения. Положение и скорость при этом отслеживаются точно. Для силового анализа нужна связь, заданная по скоростям (index-1); в текущей версии она не реализована. Численная иллюстрация — examples/linear_actuator.jl.
  • Цель должна быть совместна с остальными связями. Если целевой угол противоречит геометрии механизма, решатель будет бороться с ограничениями.
  • Начальная цель. До первого prestep действует цель, заданная в конструкторе; при старте из несогласованного состояния возможен переходный процесс.
  • Скорость цели важна. settarget! требует и значение, и его производную; несогласованная производная ломает согласованность якобиана и ухудшает точность слежения.
